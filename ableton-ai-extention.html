Why it sounds right

Most AI music tools generate noise. This one listens first.

The hard part isn't calling an LLM — it's making the output musically coherent every time. A layered reliability system handles that.

Session-aware context

Reads tempo, key, every track, and the live drum-rack pad map — plus the exact note positions of other clips (arrangement and session view) so new parts lock to what's playing.

Genre skill packs

Editable markdown knowledge (hip-hop, house, drums, bass, melody) is auto-loaded by track role and prompt, so the model reasons like a producer in that style.

Deterministic validators

Code — not prompts — guarantees the output: out-of-key notes snap to scale, flat velocities get humanized, note walls get thinned. Reliability that doesn't depend on the model behaving.

Drift-proof drums

A bar-repeating architecture defines one bar that the engine clones; fills are additive, so the kick and snare backbone can never wander across bars.

Web access

Paste a URL and the AI fetches the page mid-generation — pattern libraries, chord charts, genre references — then applies what it read.

Stays in key

Reads Live's Scale Mode and constrains every generated note to the active scale — no more out-of-key melodies dropped into your track.

Under the hood

From right-click to written MIDI.

The extension runs as a sandboxed Node.js process inside Ableton's Extension Host.

1

Read the session

Tempo, key/scale, every track, mixer state, devices, drum-rack pad pitches, and the notes playing in the same region on other tracks.

2

Load skills + prompt the model

Relevant genre skill packs are injected, then GPT is called via raw node:https (the sandbox has no fetch) with function-calling tools.

3

Browse if needed

An agentic loop resolves any fetch_url calls locally and feeds page content back until the model emits a final generation tool call.

4

Validate & write

Notes pass through deterministic validators, then are written back into Live in a single transaction — color-coded by role.
